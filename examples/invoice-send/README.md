# Invoice over WhatsApp — runnable example

A website backend that builds an invoice PDF and sends it through the gateway with a **`send`**
token. The token stays on the server; the browser only talks to your own `/api/invoice` route.

```
examples/invoice-send/
  pdf.mjs            minimal dependency-free PDF writer (one A4 page, Helvetica)
  send-invoice.mjs   CLI: build or load a PDF and POST it to /api/send
  server.mjs         Express-less HTTP server: GET / (form) + POST /api/invoice
  form.html          the form the server serves
```

## 1. Create a send token

In the dashboard: **Settings → Sending & widget → Token type: Server / app**. Pick the session
(your WhatsApp number), optionally list the chats it may message, set an expiry, and copy the
`owa_…` value — it is shown once.

Or over the API:

```bash
curl -X POST 'https://wa.example.com/api/tokens' \
  -H "x-api-key: $API_TOKEN" -H 'content-type: application/json' \
  -d '{"kind":"send","label":"Invoices","session":"support","expiresInDays":90}'
```

## 2. Send one invoice

```bash
OPENWA_URL=https://wa.example.com \
OPENWA_TOKEN=owa_… \
node send-invoice.mjs --phone 9779800000000 --amount 2500 --number INV-42
```

```
Sent invoice-INV-42.pdf (0.7 KB) in 640 ms
  message id: 3EB0…
  chat:       9779800000000@s.whatsapp.net
```

Pass `--file path/to/real.pdf` to send your own PDF (generated by Puppeteer, jsPDF, wkhtmltopdf,
your accounting app, …) instead of the built-in sample.

## 3. The website flow

```bash
OPENWA_URL=https://wa.example.com OPENWA_TOKEN=owa_… node server.mjs
# → Invoice demo on http://localhost:3000
```

Open <http://localhost:3000>, fill the form, submit. `server.mjs` validates the number and amount,
builds the PDF with `pdf.mjs`, and posts:

```json
{
  "token": "owa_…",
  "chatId": "9779800000000",
  "text": "Invoice INV-42\nAmount due: Rs 2500.00",
  "document": {
    "fileName": "invoice-INV-42.pdf",
    "mimetype": "application/pdf",
    "caption": "Invoice INV-42\nAmount due: Rs 2500.00",
    "base64": "JVBERi0xLjQK…"
  }
}
```

`POST /api/send` returns `{ ok, kind, chatId, id, fileName, bytes }`. Store `id` with the invoice so
a retry can skip work that already went out.

## Limits to remember

- 8 MiB per document after base64 decoding (`413` past it).
- 500 sends per UTC day per `send` token (`429` past it); the session's `DAILY_WAKE_LIMIT` also
  applies when the socket has to reconnect — batch a run of invoices and it shares one window.
- Text is capped at 4096 characters; captions at 1024.
- No delivery receipts: you get the WhatsApp message id.

For production, put `server.mjs` behind your own authentication and CSRF protection, and keep the
token in your platform's secret store. Full guide: [`docs/integrations.md`](../../docs/integrations.md).
